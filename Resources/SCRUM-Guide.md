# SCRUM Guide

## Overview
SCRUM is a lightweight agile framework for developing, delivering, and sustaining complex products through iterative, incremental work cycles called **Sprints**.

## Roles
- **Product Owner** — owns the Product Backlog, defines priorities, maximizes product value
- **Scrum Master** — facilitates the process, removes impediments, coaches the team
- **Development Team** — cross-functional, self-organizing group that delivers the increment

## Events
1. **Sprint** — time-boxed iteration (typically 1–4 weeks) that produces a usable increment
2. **Sprint Planning** — team defines the Sprint Goal and selects backlog items to deliver
3. **Daily Scrum** — 15-minute daily sync to inspect progress and adapt the plan
4. **Sprint Review** — demo of the increment to stakeholders, gather feedback
5. **Sprint Retrospective** — team reflects on process and identifies improvements

## Artifacts
- **Product Backlog** — ordered list of everything known to be needed in the product
- **Sprint Backlog** — set of Product Backlog items selected for the Sprint, plus a plan
- **Increment** — sum of all completed Product Backlog items during a Sprint

## Key Metrics
| Metric | Description |
|---|---|
| Velocity | Amount of work (story points) completed per Sprint |
| Burndown | Remaining work vs. time left in the Sprint |
| Burnup | Completed work vs. total scope over time |
| Cycle Time | Time from work start to completion for an item |

## User Stories
Format: `As a [role], I want [feature], so that [benefit]`

Example:
```
As a student, I want to track my study progress,
so that I can see how close I am to finishing a course.
```

## Estimation
- **Story Points** — relative sizing (Fibonacci: 1, 2, 3, 5, 8, 13, 21)
- **Planning Poker** — team consensus technique for estimating

# Guia do SCRUM

## Visão Geral
SCRUM é um framework ágil leve para desenvolver, entregar e sustentar produtos complexos através de ciclos de trabalho iterativos e incrementais chamados **Sprints**.

## Papéis
- **Product Owner** — dono do Product Backlog, define prioridades, maximiza o valor do produto
- **Scrum Master** — facilita o processo, remove impedimentos, orienta a equipe
- **Time de Desenvolvimento** — grupo multifuncional e autogerenciável que entrega o incremento

## Eventos
1. **Sprint** — iteração com prazo fixo (normalmente 1 a 4 semanas) que produz um incremento utilizável
2. **Sprint Planning** — a equipe define a Meta da Sprint e seleciona os itens do backlog a entregar
3. **Daily Scrum** — sincronização diária de 15 minutos para acompanhar o progresso e ajustar o plano
4. **Sprint Review** — demonstração do incremento aos stakeholders, coleta de feedback
5. **Sprint Retrospective** — a equipe reflete sobre o processo e identifica melhorias

## Artefatos
- **Product Backlog** — lista ordenada de tudo o que se sabe ser necessário no produto
- **Sprint Backlog** — conjunto de itens do Product Backlog selecionados para a Sprint, mais um plano
- **Incremento** — soma de todos os itens do Product Backlog concluídos durante uma Sprint

## Principais Métricas
| Métrica | Descrição |
|---|---|
| Velocity | Quantidade de trabalho (pontos de história) concluído por Sprint |
| Burndown | Trabalho restante vs. tempo restante na Sprint |
| Burnup | Trabalho concluído vs. escopo total ao longo do tempo |
| Cycle Time | Tempo entre o início e a conclusão de um item |

## User Stories
Formato: `Como [papel], eu quero [funcionalidade], para que [benefício]`

Exemplo:
```
Como estudante, eu quero acompanhar meu progresso de estudos,
para que eu possa ver o quão perto estou de terminar um curso.
```

## Estimativas
- **Story Points** — dimensionamento relativo (Fibonacci: 1, 2, 3, 5, 8, 13, 21)
- **Planning Poker** — técnica de consenso da equipe para estimar

Jira, Trello, Notion, Azure DevOps
